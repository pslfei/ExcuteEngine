# 实施计划：PCA / ANN 预警输出系统点自动登记与动态同步

日期：2026-10-15。

任务类型：后端 / 数据库数据同步 / 运行时绑定。

状态：仅规划，未修改产品代码或数据库。本版采用用户提出的Source枚举扩展：不新增表、字段、索引，不使用归属JSON文件。

## 1. 推荐方案与业务约定

在现有 `ExcuteEngine.SourceType` 枚举追加一个成员，保留原值0～3不变：

```csharp
public enum SourceType
{
    /// <summary>原始系统点。</summary>
    DCS = 0,

    /// <summary>页面输入点。</summary>
    PageInput = 1,

    /// <summary>外部系统点。</summary>
    ExternalSystems = 2,

    /// <summary>回写DCS点。</summary>
    WriteBack = 3,

    /// <summary>自动创建的PCA / ANN模型预警输出系统点。</summary>
    ModelAlarmOutput = 4
}
```

本功能新建系统点时写入 `cfg_varsystem.Source = (int)SourceType.ModelAlarmOutput`。这是新增一个来源类别，不改变已有来源类别的含义，也不占用其他业务字段。

`CfgVarsystem.Source` 已为可空整数，当前EF映射未将其限制为0～3；无需数据库结构迁移。实施前只读核对实际数据库字段及Source=4的既有数据，确认没有与库外应用约定冲突。

### 托管与人工接管

- `Source == ModelAlarmOutput`：表示仍由本功能自动托管。
- `Source` 为NULL或其他值：不属于本功能的自动更新/删除对象。
- 人工要接管一个自动点，应先将Source改为合适的现有来源值，再编辑配置。
- 只改Description而保留Source=4，不视为人工接管；自动同步仍会按模型更新托管字段。
- 不再保存跨重启配置快照，因此不能宣称能自动识别所有“人工修改过、但仍标记为4”的记录。
- 对自动点中出现的外部IO映射、强制值等非默认业务配置，保守保护并报告，提示明确人工接管，不直接清理。
- 已有人工同名点不会自动改成Source=4；类型和控制器兼容时可复用绑定，原配置保持人工管理。
- 过去已经创建但Source不是4的点，不凭名称批量接管。确需接管时单独审阅后修改Source，不纳入默认同步。

## 2. 结构化需求

1. 查询FunctionName以PCA或ANN开头的算法块，关联输出表，只处理 `^OUT_W[0-9]+$`。
2. 点名严格使用 `AlgName + "#" + PinName`。
3. 按输出记录ID更新 `cld_fcoutput.PointName`。
4. 新系统点写入现有字段：
   - Name：生成点名。
   - DataType：LD。
   - Description：`(BlockDesc ?? "") + (PinDesc ?? "")`，直接拼接。
   - Prj_Controller_ID：算法块所属控制器。
   - Source：ModelAlarmOutput，即4。
5. 启动时在 `InitSystemPoint()` 前完成数据库同步。
6. 运行中模型、预警输出管脚及托管元数据变化时，动态同步数据库、RTD及相关绑定。
7. 重复同步不重复插入；无变化不写库、不重建模型、不替换LD对象。
8. 清理失效自动点，同时保护人工点、已接管点和仍被其他逻辑引用的点。
9. OUT_W输出要直接反映到系统点，不依赖启用DCS回写。
10. 不修改PCA/ANN算法公式、故障报警确认和挂起规则，不删除历史数据。

## 4. 自动归属与清理条件

### 4.1 当前有效点集合

由算法块及输出表生成完整有效集合：

```text
有效点名 = 当前所有PCA/ANN实例的 AlgName#OUT_W数字
```

生成时保留输出ID、算法块ID、工作表ID和控制器ID，用于本轮差异与运行时更新；不额外持久化归属表或文件。

不能只判断AlgName是否存在：算法块仍在，但OUT_W2已经删除时，旧的AlgName#OUT_W2也属于失效候选。

### 4.2 删除判定

```text
可以删除 =
    Source == ModelAlarmOutput
    且 Name符合约定的AlgName#OUT_W数字格式
    且 DataType为LD
    且 Name不在当前有效点集合中
    且 没有需要保护的额外业务配置
    且 数据库和全部运行时控制器都没有其他引用
    且 检查全部成功
```

上述条件是“同时满足”。Source标记、名称规则和有效集合解决归属与失效判断；引用检查仍不可省略。

### 4.3 示例

| 系统点 | Source | 当前生产者情况 | 引用 | 处理 |
| --- | --- | --- | --- | --- |
| ANN160_1#OUT_W1 | 4 | 实例及管脚存在 | 任意 | 保留，按模型更新托管字段 |
| ANN160_1#OUT_W2 | 4 | 实例存在，OUT_W2删除 | 无 | 可清理 |
| ANN160_1#OUT_W1 | 4 | 实例已删除 | 有 | 保留点及引用对象，报告失效生产者 |
| ANN160_1#OUT_W1 | 0/NULL/其他 | 任意 | 任意 | 不由本功能清理或覆盖 |
| 人工改名后的点 | 4 | 名称不符合约定 | 任意 | 保守保留，提示来源标记与名称不一致 |
| ANN160_1#OUT_W1 | 4 | 已失效，带人工IO/强制等配置 | 无 | 保留并提示人工接管 |

### 4.4 人工点与额外配置

- 不覆盖Source不为4的人工同名点。
- 自动点的Name、DataType、Description、Prj_Controller_ID按本功能约定管理；有效点中类型不是LD时报告冲突，不直接替换对象。
- 不通过重建整行更新记录，默认值、IO映射、强制值、历史/报警设置等非托管字段不覆盖。
- 判定“额外业务配置”时参考实际库及创建时默认值，不能把数据库默认0误判为人工修改。
- 无法确定是否安全时保留并报告；不把“仍为4”解释为允许删除有引用或带明显人工配置的点。
- 人工接管后Source改变，同步服务在更新/删除前必须再次确认来源仍为4，防止扫描之后发生接管又被覆盖。

## 5. 引用检查

覆盖数据库配置与全部控制器，而非只调用现有GetReference：

- cld_fcinput.PointName：直接点名、列表、表达式；包括未下装工作表。
- cld_fcoutput.PointName：除本轮明确移除/改写的生产者之外的其他输出。
- cld_fcparameter.Pvalue及cld_fcblock.InstantInfo中的可识别点名/条件。
- cld_warnpoint的点名、输出点、回写点及条件。
- parawarns、troubleshooting等相关回写/点名配置。
- pointshow、点操作指导等相关配置。
- 全部控制器UsedPointsByFc、健康度UsePoint/条件、已加载Excel报警配置。

既识别AlgName#PinName系统点引用，也核对相关AlgName.PinName内部连接别名。条件、列表和JSON按现有语法识别完整点名，避免裸子串匹配误判。

未知语法、引用数据读取失败或范围不完整时不删除。待清理点在引用解除后再次评估，即使模型配置指纹没有变化。

失效但被引用的点保留数据库记录及运行对象，不自动改写下游输入、停用算法或清除报警。来源消失后旧点不能继续获得该模型输出，须报告孤立状态。

## 6. 数据库同步

1. 批量查询期望模型输出、相关系统点及Source=4的已有点。
2. 校验空名称、50字符限制、保留分隔符、大小写不敏感重名和多生产者冲突。
3. 计算新增、托管更新、无变化、人工复用、冲突、失效保留和可删除。
4. 启动关键冲突时明确失败，不进入部分配置的初始化；动态失败保留原运行状态并报告。
5. 在同一事务中更新输出PointName，新增Source=4系统点，更新有效自动点元数据，最后清理满足条件的失效自动点。
6. 更新/删除前重新核对Source、引用和必要配置，处理并发人工编辑；数据库层面的写入应包含来源保护，不只依赖早期内存判断。
7. 数据库失败回滚，不发布新的运行时配置。
8. 返回结构化差异与保护/冲突原因。

实例/管脚改名时创建新点名，旧点按清理规则判断，不通过原地改名破坏其他逻辑的引用。控制器变化但点名不变时更新托管控制器信息并核对绑定。

既有同名人工点只在LD类型、控制器、IO和生产者均兼容时复用，Source不变、描述不覆盖；否则报告冲突。

## 7. 启动与运行时绑定

### 启动顺序

```text
读取配置
→ 同步模型预警输出（数据库事务，新增点Source=4）
→ InitSystemPoint()
→ 初始化控制器/模型
→ 绑定OUT_Wn与系统LD对象
→ 开始运行
```

### 直接绑定与内部点隔离

- 复用LDEx系统点创建逻辑；已有同名兼容对象保持不变。
- OUT_Wn字段与RTDDict中系统LD对象直接绑定，模型与下游逻辑共享同一对象。
- 反射检查管脚存在且类型兼容；模型重载后新输出重新绑定原系统对象。
- 关闭enableWriteBackDcs时仍能更新系统点。
- 自动内部点不加入外部采集，不被外部响应覆盖，也不发送到外部DCS回写接口。
- 不能仅按Source=4过滤所有情况：兼容人工点被复用为有效模型输出时，同样要防止外部IO与模型双重驱动；采用有效生产者集合及Source=4托管集合共同判定，冲突时拒绝绑定。
- 新增点先加入RTD再绑定；描述变化不替换LD对象。
- 只更新受影响模型、管脚和引用方，不重新执行整个InitSystemPoint或重建所有PCA/ANN。
- 清理数据库后再清理缓存与旧生产者绑定；有引用的对象保留。
- 模型DLL未加载时报告绑定待完成，不宣称整体成功，也不在此功能中自动重写模型编译。

数据库与内存不能共同事务：数据库成功、运行时失败时保留待应用变更并补偿；仅在两者都成功后推进已应用指纹。重启后依靠数据库Source和当前配置恢复，无需JSON归属文件。

## 8. 动态触发与并发

### 即时入口

统一接入ReloadModel、ReinitializeSheet、ReinitializeSheets和ReinitializeSheetsIncremental。在重新读取工作表配置和绑定前完成同步，合并批量范围，防止递归重复同步。

Controller直接入口也要遵守同一协调规则，避免runSync与生命周期锁反向获取。

### 低频检测（仍为建议选项）

暂按接口即时同步加可配置30秒检测规划，覆盖直接改库而未调用接口的情况。无变化不写库、不重绑、不重建；被引用保护的失效点仍需复查。

任务单实例、可停止、无重叠；数据库及运行时都完成后才更新指纹。

### 锁边界

- 数据库查询和事务不持有FaultAlarmSync。
- 生命周期/同步任务串行，运行时只使用受影响控制器及块的局部锁。
- 不在持有全局锁时等待块锁，不恢复整执行周期的全局锁。
- 多控制器/块按固定ID顺序更新。
- 多进程管理同一库仍需部署唯一同步写入节点或数据库级协调，Source字段本身不是并发锁。

## 9. 实施步骤

1. **来源与数据预检**：核对实际Source字段、值4使用情况、点名长度、重复点名及外部消费者来源约定。
2. **扩展来源枚举**：追加ModelAlarmOutput=4；现有成员及普通人工/导入点的来源不变。
3. **实现差异与清理判定**：Source+名称+有效集合+配置保护+引用检查，提供结构化结果。
4. **实现事务同步**：更新输出表、新建Source=4点、更新有效托管元数据、安全清理。
5. **启动接入**：在InitSystemPoint前调用，失败不继续部分初始化。
6. **运行时绑定**：复用LD创建、绑定OUT_W、保留对象身份，隔离外部采集/写回。
7. **动态入口接入**：只更新真正变化的实例、管脚、引用方；绑定失败可补偿。
8. **检测任务**：按最终选择增加可配置低频检测与失效点复查。
9. **测试与交付**：验证事务、并发接管、引用保护、对象绑定；回归故障确认/挂起及锁优化，完善文档。

## 11. 风险与边界

| 风险 | 处理 |
| --- | --- |
| Source=4已被库外应用占用 | 实施前核对，不能覆盖已有不同语义数据 |
| 外部前端/服务只识别0～3 | 核对并补齐新来源类别展示/校验，原值保持不变 |
| 人工点也使用生成名称 | Source不是4就不接管、不清理 |
| 人工改了自动点描述但保留Source=4 | 明确仍为自动托管，模型同步可更新描述；接管须改Source |
| 无快照，无法追溯所有人工编辑 | 不承诺自动识别任意修改；保留非托管字段，明显额外配置或未知情况不清理 |
| 同名多条、类型/控制器/IO冲突 | 报告失败，禁止选第一条或强制覆盖 |
| 引用遗漏 | 数据库与所有控制器联合核对，不确定时保留 |
| 来源消失但下游仍引用 | 保留点和对象并报告孤立状态，不假装仍有生产者 |
| DB提交成功但运行时应用失败 | 待应用变更补偿，成功后再推进指纹 |
| 低频同步重置无变化模型 | 无变化零写入，局部绑定，禁止全工作表定时重建 |

## 12. 验收与验证

- 数据库表结构完全不变，未增加归属文件。
- Source原值0～3不变，新自动点为4，既有人工同名点来源不变。
- 启动时输出表和系统点先于InitSystemPoint就绪。
- PCA/ANN多个OUT_W正确登记；其他算法和输出管脚不处理。
- 点名、LD类型、描述拼接和所属控制器正确。
- 重复同步零重复、零无效更新。
- OUT_W删除但模型仍存在时能识别失效点。
- 模型删除、改名或输出变化后，仅清理Source=4且无配置/引用保护的失效点。
- 跨控制器、未下装、表达式、直接内部连接等引用均覆盖。
- 引用解除后，即使模型指纹未变，失效点仍能清理。
- Source改为其他值后停止自动管理；并发接管不会被旧扫描覆盖。
- 描述修改但Source仍4时按托管规则同步，不声称已识别为接管。
- 非LD、异常名称或带额外业务配置的失效自动点保守保留并报告。
- 数据库失败回滚；运行时失败可补偿。
- 关闭DCS回写时输出仍实时生效，外部采集/写回不覆盖内部点。
- 重载后保留系统LD对象身份，不重置无变化的报警、延时或挂起状态。
- 构建、差异检查及现有故障报警回归通过；真实MySQL隔离库验证事务及并发。
- 仅规划阶段不执行上述测试、改库或启动程序。

## 13. 部署与回退

- 无结构脚本、无归属文件部署；先核对Source新值兼容性，再更新应用。
- 首次同步输出新增、人工复用、冲突和受保护项；不把历史同名点批量标为4。
- 自动点人工接管时明确修改Source，保留必要配置。
- 回退时停止检测任务，审阅Source=4数据及输出点名变更，不批量删除所有带#OUT_W的点。
- 旧版程序可能不识别来源4；回退前核对来源处理，不能不经审阅将4全部改成DCS。
